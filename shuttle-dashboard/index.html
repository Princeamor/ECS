SIMULATION ONLY
No physical shuttle is controlled. Simulated feedback can advance ECS/WES/WMS tasks and test inventory. Use only with isolated test databases and equipment networks. Unsupported messages are logged and faulted, never reported as successful.

1. Configure an isolated test shuttle

Match the numeric shuttle ID and protocol mode to the ECS test device. Supply the enabled test-map nodes explicitly; no warehouse map is assumed.

2. Test feedback

Connect the dashboard to see simulator status.

Recovery leaves unfinished work paused until you resume. Restarting the service always disarms feedback. Only one TCP client is accepted.

ECS endpoint

In the isolated ECS device configuration, use 192.2.5.1:19080 instead of the equipment endpoint. The browser URL and webserver port are not the shuttle endpoint.

This service accepts ECS peer 192.2.5.7 and localhost only. No ECS device records or warehouse databases are edited by this dashboard.

3. Enter WMS tasks and follow the workflow

Use the warehouse applications with your own sign-in. This dashboard does not store warehouse credentials, submit inventory changes, or force task completion.

Enter a WMS relocation WMS tasks WES instructions ECS tasks
  1. Select PSA Show Room in WMS, then the second floor.
  2. Select the occupied test pallet, choose its relocation action, and select the available destination. The configured test pair is 1-3-2 and 2-3-2.
  3. Submit once. Follow the WMS MOV... task code through WES and ECS. Check all three applications for completion and the updated pallet location.
  4. Use the application exchanges below and the simulator journal to diagnose a waiting or failed task. A heartbeat or socket write alone is not success.

Only same-floor test relocations are supported here. Inbound/outbound conveyors and hoists are not emulated. The user-approved isolated-test pallet relocation limit is 100; the dashboard does not reset or bypass it.

UTC timestamps, peer addresses, raw receive chunks, decoded frames, transmit attempts, completed writes, state transitions, and errors are stored outside the web root. A completed socket write is not proof ECS accepted a message. The table shows the latest 300 events; downloads include the complete journal snapshot. The TCP download includes both directions, heartbeats, connection events and protocol errors regardless of the task-focused checkbox.
